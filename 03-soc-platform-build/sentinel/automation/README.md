# Microsoft Sentinel – Automation

## Project Overview

This implementation demonstrates how Microsoft Sentinel Automation Rules streamline Security Operations Center (SOC) workflows by automatically performing predefined actions when security incidents are created or updated. Automation reduces repetitive manual tasks, improves incident response consistency, and enables analysts to focus on higher-value investigations.

---

## Objectives

* Explore Microsoft Sentinel Automation.
* Understand Automation Rules.
* Review Playbook integration.
* Configure Automation Rules.
* Validate automation functionality.
* Document the complete implementation.

---

* Microsoft Sentinel

---

## Implementation Steps

### 1. Automation Overview

The Automation workspace was reviewed to understand how Microsoft Sentinel automates incident handling through Automation Rules and Playbooks.

---

### 2. Automation Rules

The Automation Rules page was examined to understand how incidents can automatically trigger predefined actions based on conditions and priorities.

---

### 3. Rule Configuration

The available Automation Rule configuration options were reviewed, including:

* Trigger
* Conditions
* Actions
* Rule Order
* Expiration
* Enable/Disable Status

---

### 4. Playbook Integration

The relationship between Automation Rules and Azure Logic Apps playbooks was reviewed. Automation Rules can invoke playbooks to automate investigation and response activities.

---

### 5. Automation Validation

The Automation workspace was validated by confirming the availability of Automation Rules and Playbooks within Microsoft Sentinel.
